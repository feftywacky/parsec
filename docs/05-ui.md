## 2. Charts

### 2.1 Correction: `PlotCandlestick` is not ImPlot API

Candlesticks are **not in the ImPlot library.** `PlotCandlestick` lives in `implot_demo.cpp`
inside `namespace MyImPlot` — it is sample code you are expected to copy. Two related
corrections, both ✅ verified against `implot.h` at v1.0:

- **`ImPlot::PlotRects` does not exist.**
- **`ImPlotFlags_NoChildren` no longer exists** (`grep -c NoChildren implot.h` → `0`).

Upstream reference: `implot_demo.cpp` — declaration line 86, implementation line 2997, call
site line 2730.

**⚠️ v1.0 breaking change.** `BeginItem` is now
`bool BeginItem(const char* label_id, const ImPlotSpec& spec = ImPlotSpec(), const ImVec4& item_col = IMPLOT_AUTO_COL, ImPlotMarker item_mkr = ImPlotMarker_Invalid)`.
v1.0 replaced all `PushStyleVar`/`PushStyleColor` item styling with `ImPlotSpec`
(PR #519). Candlestick code copied from any pre-2026 blog post **will not compile.**

`BeginItem`/`EndItem`/`FitThisFrame`/`FitPoint`/`AddLineV` are internal API — they need
`#include "implot_internal.h"`.

### 2.2 Use ImPlot, replace only its render loop

The demo's `PlotCandlestick` *is* hand-rolled `ImDrawList` code that happens to live inside
`BeginItem`/`EndItem`. So the "ImPlot vs raw ImDrawList" question mostly dissolves: staying
inside ImPlot gets you axis ticks and labels, time formatting, pan/zoom/box-select, legend,
`GetPlotLimits`, log scale, and axis constraints for free. Rebuilding those is days of work.

**Approach: copy `PlotCandlestick` into `src/ui/widgets/candles.cpp` and replace its render
loop with the clipped/LOD version below.** Use raw `ImDrawList` only for overlays — order
lines, position markers, liquidation price — drawn via `ImPlot::GetPlotDrawList()` between
`BeginPlot`/`EndPlot` so they share the plot transform.

### 2.3 Plot setup

```cpp
ImPlot::GetStyle().UseLocalTime = false;              // exchange data is UTC

if (ImPlot::BeginPlot("BTC-PERP", ImVec2(-1,0), ImPlotFlags_Crosshairs)) {
    // RangeFit (1<<12) is the important one: fit Y only to points visible in X —
    // i.e. "auto-scale price to what I'm looking at", which is what traders expect.
    ImPlot::SetupAxes(nullptr, nullptr, 0,
                      ImPlotAxisFlags_AutoFit | ImPlotAxisFlags_RangeFit);
    ImPlot::SetupAxisScale(ImAxis_X1, ImPlotScale_Time);    // unix seconds as double
    ImPlot::SetupAxisScale(ImAxis_Y1, ImPlotScale_Log10);   // log price toggle
    ImPlot::SetupAxisFormat(ImAxis_Y1, "$%.2f");
    ImPlot::SetupAxisLimitsConstraints(ImAxis_X1, t_first, t_last);
    ImPlot::SetupAxisZoomConstraints(ImAxis_X1, 60*60*24*14, t_last - t_first);
    PlotCandlestickLOD("BTC", bars, t0, dt, kBull, kBear);

```
✅ `enum ImPlotScale_ { Linear = 0, Time, Log10, SymLog }` at `implot.h:430`.

**`ImPlotFlags_Crosshairs` only swaps the mouse cursor.** A real trading crosshair — full-width
and full-height lines with price and time labels pinned to the axes — is hand-drawn:

```cpp
    dl->AddText({pos.x+size.x-48, px.y-7}, IM_COL32_WHITE, buf);

```

### 2.4 Viewport clipping + LOD — the highest-leverage thing in the chart

The stock demo loops over **every** candle and calls `PlotToPixels` on each, so 50 000 candles
means 50 000 transforms and 100 000 draw primitives per frame *regardless of zoom*. That is the
reported "50k entries → 30 FPS" behaviour (ImPlot issue #290).

`ImPlot::GetPlotLimits()` gives the visible X range. Because candle timestamps are uniformly
spaced, finding the index bounds is O(1) arithmetic — no binary search needed:

```cpp
void PlotCandlestickLOD(const char* id, const Bars& b, double t0, double dt,
                        ImVec4 bull, ImVec4 bear)
{
    ImPlotRect lim = ImPlot::GetPlotLimits();

    // --- viewport clip: O(1) index math ---
    int i0 = (int)std::floor((lim.X.Min - t0) / dt) - 1;
    int i1 = (int)std::ceil ((lim.X.Max - t0) / dt) + 1;
    i0 = std::clamp(i0, 0, b.count - 1);
    i1 = std::clamp(i1, 0, b.count - 1);
    if (i1 <= i0) return;

    // --- LOD: never draw more candles than we have pixels for ---
    float plot_w = ImPlot::GetPlotSize().x;
    int   stride = std::max(1, (int)std::ceil((i1 - i0) / std::max(plot_w * 0.5f, 1.0f)));

    ImDrawList* dl = ImPlot::GetPlotDrawList();
    double half_w = dt * 0.5 * 0.7;                       // 70% body width

    if (ImPlot::BeginItem(id)) {
        if (ImPlot::FitThisFrame())
            for (int i = i0; i <= i1; ++i) {
                ImPlot::FitPoint(ImPlotPoint(b.t[i], b.low[i]));
                ImPlot::FitPoint(ImPlotPoint(b.t[i], b.high[i]));
            }

        for (int i = i0; i <= i1; i += stride) {
            int j = std::min(i + stride, i1 + 1);
            double o = b.open[i], c = b.close[j-1];
            double lo = b.low[i], hi = b.high[i];
            for (int k = i+1; k < j; ++k) {               // aggregate the bucket
                lo = std::min(lo, b.low[k]); hi = std::max(hi, b.high[k]);
            }
            ImU32 col = ImGui::GetColorU32(o > c ? bear : bull);
            ImVec2 a = ImPlot::PlotToPixels(b.t[i] - half_w, o);
            ImVec2 d = ImPlot::PlotToPixels(b.t[i] + half_w * (2*stride - 1), c);
            ImPlot::AddLineV(dl, (float)ImPlot::PlotToPixels(b.t[i], 0).x,
                             (float)a.y, (float)d.y, col);
            if (std::abs(d.y - a.y) < 1.0f) d.y = a.y + 1.0f;   // doji stays visible
            dl->AddRectFilled(a, d, col);
        }
        ImPlot::EndItem();
    }
}
```

**Cost is bounded by pixel width, not dataset size.** A 1600 px chart draws at most ~800
candles whether the backing array holds 200 or 5 000 000.

> ⚠️ The 30-FPS-at-50k figure is a user report (ImPlot #290), not a measurement, and the LOD
> version above is sound by construction but its actual frame cost is **unmeasured**. Benchmark
> it in Phase 2 rather than assuming.

### 2.5 The 64K vertex ceiling — already handled ✅

`ImDrawIdx` defaults to `unsigned short` (`imgui.h:3196`), i.e. 65 535 indices per draw
command, and 10 000 candles would blow past that. **You do not need
`#define ImDrawIdx unsigned int`**: the OpenGL3 and Metal backends both set
`ImGuiBackendFlags_RendererHasVtxOffset` (`1<<3`) and honour `ImDrawCmd::VtxOffset`, which lets
ImGui emit unlimited-size meshes with 16-bit indices. The only way to break this is to write a
custom renderer that ignores `VtxOffset`.

## 4. Idle cost

A naive ImGui loop calls `glfwPollEvents()` and spins at vsync forever, burning a core. A
trading terminal wants the opposite default: **idle at ~10 fps, jump to 60 fps when something
changes.**

```cpp
constexpr double kIdleFps = 10.0, kActiveFps = 60.0;
std::atomic<bool> g_dirty{false};                 // set by the engine thread

while (!glfwWindowShouldClose(win)) {
    bool active = g_dirty.exchange(false) || ImGui::GetIO().WantTextInput;
    glfwWaitEventsTimeout(1.0 / (active ? kActiveFps : kIdleFps));
    /* NewFrame -> DrawTerminal() -> Render -> SwapBuffers */
}
```

✅ Verified in the local GLFW 3.5.1 header: `glfwWaitEventsTimeout(double)` (glfw3.h:4641)
blocks until an event or timeout; **`glfwPostEmptyEvent(void)`** (glfw3.h:4661, since 3.1) is
the key primitive — the documented way to wake `glfwWaitEventsTimeout` from another thread.

The engine thread writes its snapshot, sets `g_dirty`, then calls `glfwPostEmptyEvent()`. That
gives sub-frame latency on a fill while still idling at 10 fps when the book is quiet.

Two refinements:
- **Do not wake the renderer on every book delta.** At 100+ updates/s you would render above
  60 fps and waste the whole optimization. Rate-limit `glfwPostEmptyEvent` to ~60 Hz, or let
  the timeout coalesce bursts naturally.
- `glfwWaitEventsTimeout` must run on the main thread, and on macOS specifically the thread
  that created the window. This forces "render on main, everything else on workers" — which is
  the right architecture anyway (02 §4).

Upstream: ImGui's position is that idling is deliberately the application's job, so there is no
built-in flag — see the "Implementing Power Save" wiki page.

## 5. Cross-thread structures

### 5.1 Seqlock — "latest order-book snapshot"

The renderer only ever wants the *newest* book, never a history, so a queue is the wrong shape.
A seqlock never blocks the writer and uses no bus-locked instructions.
Reference implementation: `rigtorp/Seqlock` (header-only, MIT).

```cpp
template <typename T> class Seqlock {
  static_assert(std::is_nothrow_copy_assignable<T>::value);
  static_assert(std::is_trivially_copy_assignable<T>::value);
public:
  T load() const noexcept {
    T copy; std::size_t seq0, seq1;
    do {
      seq0 = seq_.load(std::memory_order_acquire);
      std::atomic_signal_fence(std::memory_order_acq_rel);
      copy = value_;
      std::atomic_signal_fence(std::memory_order_acq_rel);
      seq1 = seq_.load(std::memory_order_acquire);
    } while (seq0 != seq1 || seq0 & 1);          // odd == write in progress
    return copy;
  }
  void store(const T& desired) noexcept {
    std::size_t seq0 = seq_.load(std::memory_order_relaxed);
    seq_.store(seq0 + 1, std::memory_order_release);      // -> odd
    std::atomic_signal_fence(std::memory_order_acq_rel);
    value_ = desired;
    std::atomic_signal_fence(std::memory_order_acq_rel);
    seq_.store(seq0 + 2, std::memory_order_release);      // -> even
  }
private:
  static const std::size_t kFalseSharingRange = 128;      // Apple Silicon cache line
  alignas(kFalseSharingRange) T value_;
  std::atomic<std::size_t> seq_;
  char padding_[/* pad to a multiple of 128 */];
};
```

The `static_assert`s enforce trivially-copyable, which conveniently forces `L2Book` off
`std::vector` and onto the fixed-size layout we wanted anyway (02 §6.1).

> ⚠️ **Pedantic but real:** `value_ = desired` is a non-atomic write racing a non-atomic read,
> which is formally UB under the C++ memory model even though it is correct on every real
> architecture. Rigtorp documents this. If it bothers you, the alternative is a triple buffer
> with an atomic index swap — no torn reads, no UB, one extra buffer of memory. Either is
> defensible; pick one deliberately rather than by accident.

### 5.2 SPSC ring — fills, acks, toasts

For streams where *every* item matters, use a bounded SPSC queue. `rigtorp/SPSCQueue`
(header-only, C++11, MIT) caches head/tail locally to cut coherency traffic and pads both
indices and the slot buffer against false sharing.

```cpp
rigtorp::SPSCQueue<Fill> fills{4096};
// engine: if (!fills.try_emplace(f)) ++dropped;  then rate-limited glfwPostEmptyEvent()
// render: while (Fill* f = fills.front()) { apply(*f); fills.pop(); }
```

`moodycamel::ReaderWriterQueue` is a fine alternative; `ConcurrentQueue` is MPMC and more
machinery than needed. Prefer rigtorp's here — smaller, and the cache-line discipline is
explicit and auditable.

### 5.3 No allocation on the hot path

- Preallocate every ring and snapshot at startup. `try_push` returning false is backpressure,
  not a resize signal.
- **The C++ side never parses market-data JSON at all** — Rust does it at the edge and hands
  over POD structs (04 §5). So `nlohmann::json` is confined to config and CLI, where its
  per-node allocation is irrelevant. This is a real benefit of the language split that is easy
  to forget: no `simdjson`, no SAX handler, no DOM on the hot path, because there is no JSON on
  the hot path.
- ImGui reuses its draw buffers across frames, so steady-state frames do zero `malloc` as long
  as panel code doesn't allocate.

**FetchContent over vcpkg or Conan.** For a solo project with five dependencies, FetchContent
is the only option with zero out-of-band state: `git clone && cmake -B build` works on a fresh
machine and in CI with no manifest tool, toolchain file, or lockfile daemon. vcpkg earns its
keep with many heavy binary deps and a binary cache; Conan with multi-package versioning across
teams. Neither pays for itself here. `GIT_SHALLOW TRUE` roughly halves clone time (~33 s cold,
near-zero warm).

## 7. Build gotchas, all hit and verified

**1. The Objective-C++ trap — and why GLFW+OpenGL3 avoids it.** ✅ If you add
`imgui_impl_metal.mm`, `-fobjc-arc` guarded by `$<COMPILE_LANGUAGE:OBJCXX>` **silently does
nothing** unless `OBJCXX` is an enabled language — CMake compiles the `.mm` as plain C++ and
you get `'__bridge_retained' casts have no effect when not using ARC`. Adding
`LANGUAGES C CXX OBJCXX` then **breaks GLFW**, because CMake starts compiling GLFW's `.m` files
as Objective-C++ (errors like `cannot initialize 'CFStringRef *' with an rvalue of type
'void *'`). The only correct incantation is `LANGUAGES C CXX OBJC OBJCXX`. This is a concrete
argument for decision D3 beyond portability.

**2. CMake 4.x and `cmake_minimum_required`.** CMake 4 removed compatibility with
`cmake_minimum_required(VERSION <3.5)`. ✅ The pinned deps here are fine — GLFW 3.5.1 declares
`3.16...3.28`, and even GLFW 3.3.10 configures cleanly because the *range* form is tolerated.
The failure mode is a dep declaring a bare `VERSION 3.0` with no upper range. Escape hatch,
✅ confirmed accepted: `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`, or scope it to the offending dep
with `set(...)` / `unset(...)` around its `FetchContent_MakeAvailable`. Treat it as a temporary
unblock, never a permanent setting.

**3. Pin every `GIT_TAG` to a tag or SHA, never a branch** — with the sole exception of imgui,
where `docking` *is* the release channel. Pin `v1.92.9b-docking` for reproducibility.

**4. Corrosion `v0.5.2`** — the tag was not verified to exist; check before pinning
(`v0.6.1` is current). The `corrosion_import_crate` API and the
`crate-type = ["staticlib"]` requirement come from the docs, and a working
CMake+Corrosion+tokio build is preserved at `prototypes/ffi-demo/`.

**5. Linux is unbuilt.** Everything above was compiled on macOS only. GLFW+OpenGL3 is the
well-trodden path and should port cleanly, but **no Linux build has been run** — do it in
Phase 0 rather than discovering it in Phase 5.

**6. No C++ WebSocket library is needed.** IXWebSocket and Boost.Beast were surveyed, but all
socket work lives in Rust (04). Adding either would duplicate the transport layer.
