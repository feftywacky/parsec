# Parsec — UI

Dear ImGui over GLFW/OpenGL3. Layout mirrors the Hyperliquid web terminal
(02 §7). Everything marked ✅ was compiled and run on macOS 15 / Apple Silicon /
AppleClang 21 / CMake 4.1 during research.

## 2. The chart

Hand-rolled on `ImDrawList`, in `src/ui/widgets/chart.cpp` (rendering and input) and
`src/ui/widgets/chart_scale.cpp` (axis arithmetic, ImGui-free and unit-tested in
`tests/cpp/test_chart_scale.cpp`). Geometry and interaction numbers below are read from
TradingView's Lightweight Charts source, which is the reference implementation of this design.

### 2.1 X is a bar index, not a timestamp

This is the decision the whole chart falls out of. The view is two scalars:

```
bar_spacing   float   pixels per bar     -- the zoom
right_offset  double  bars of empty pane -- the pan, measured from the NEWEST bar
```

Everything else is derived: `right_bar = (n-1) + right_offset`, `left_bar = right_bar -
plot_w / bar_spacing`, and bar `i` sits at `x0 + (i - left_bar) * bar_spacing`.

Consequences, all of them things a trader expects and a continuous time axis cannot give:

- A gap in the series — a venue outage, a reconnect, a stretch this client was unsubscribed
  for — **collapses**. There is no hole, and no bar changes width because of one.
- Every bar is the same width at a given zoom, so the candles read as a uniform texture.
- Zoom is "pixels per bar", which is the quantity the body/wick geometry is defined against.
- Bounding `bar_spacing` below at 1 px bounds the draw loop: at most `plot_w` bars are ever
  visible, so there is no level-of-detail bucketing and no aggregated pseudo-bars.

**This is why ImPlot was dropped.** ImPlot's X is continuous; `ImPlotScale_Time` opens holes
across gaps, item widths are expressed in plot units so they rescale under zoom, and
`Locator_Default` targets one major tick per 300 px on a vertical axis where a price scale
wants one per 30. Driving it correctly means locking both axes with `ImPlotCond_Always` (which
disables ImPlot's own pan/zoom), supplying every tick through `SetupAxisTicks`, and drawing
every mark through `GetPlotDrawList()` — at which point ImPlot contributes a frame and a clip
rect, for a dependency, a `demo.cpp` translation unit and a second coordinate system to keep in
sync. It is no longer fetched or linked.

### 2.2 Following the live edge

`right_offset` is measured from the newest bar, so when a bar prints the window comes with it
for free — the chart follows. When the newest bar has been scrolled off screen the offset is
compensated by the number of bars that printed, so the view holds still. That one rule replaces
a "follow" mode flag and every re-seed/auto-fit workaround around it.

New bars are counted by looking the previous newest `open_ms` back up, not by differencing
`count`: `md::CandleSeries` is a fixed-capacity ring, so once it is full a new bar leaves the
count unchanged and shifts every index down by one instead.

The jump-to-realtime chip (bottom right of the pane, shown when the offset has drifted more
than a bar from its home) animates the offset back over 400 ms.

### 2.3 Interaction

| Gesture | Effect |
|---|---|
| Wheel over the pane | Zoom time ×1.10 per notch, anchored on the bar under the cursor. Never touches price. |
| Wheel over the price axis | Zoom price ×1.10 per notch, anchored on the cursor, and **lock auto-fit off** |
| Wheel over the time axis | Zoom time, anchored on the right edge |
| Shift+wheel, horizontal wheel | Pan time |
| Drag in the pane | Pan time; pans price too, but **only** once the price axis is locked |
| Drag the price axis | Scale price about the pane centre, and **lock auto-fit off** |
| Drag the time axis | Scale bar spacing by how much closer to the right edge the cursor came |
| Shift+drag in the pane, or the `measure` button | The ruler (§2.7) |
| Double-click the pane | Full reset |
| Double-click the price axis | Auto-fit back on |
| Double-click the time axis | Default zoom, back to the live edge |
| `Esc` | Clear the ruler |

The two subtleties worth keeping: a vertical drag does nothing while the price axis is
auto-fitting (otherwise the fit undoes it next frame and the axis feels nailed down), and
dragging the price axis is what turns auto-fit off (otherwise a manual scale can never be
held). Axis drags scale from a range snapshotted at drag start, so a long drag is a function of
total travel rather than of frame count.

### 2.4 Candle geometry

```cpp
// TradingView's optimalCandlestickWidth: coefficient eases 1.0 -> 0.8 as bars widen
if (bar_spacing >= 2.5 && bar_spacing <= 4) w = 3;
else w = min(floor(bar_spacing * (1 - 0.2*atan(max(4, bar_spacing) - 4)/(pi/2))),
             floor(bar_spacing));
if (w >= 2 && w is even) w -= 1;   // odd, so the 1px wick centres on the body
```

- Wick is **always 1 px**, drawn as an `AddRectFilled` on integer coordinates (an `AddLine` at
  thickness 1 lands on half-pixels and blurs). Drawn before the body, which covers its middle.
- Minimum body height is 1 px, so a doji renders as a hairline rather than vanishing.
- No borders. At DPR ≥ 1 they cost a draw call per candle and are invisible, since
  TradingView's own default border colour equals the fill.
- Candle colours are `#26A69A` / `#EF5350`, **not** the app's long/short palette. Hyperliquid's
  own terminal does exactly this: candles are a texture you scan, chrome is a signal you act
  on, and giving them the same green makes the chart compete with the book and the P&L.
- Price margins are fractions of pane *height*, not of the price range: 10 % top, 25 % bottom
  with the volume overlay on (which occupies the bottom 20 %), 8 % bottom without.

### 2.5 Axes

**Price** (`price_ticks`). Tick values are `Px` on the 1e8 grid, never doubles — an axis label
is a price, and a price round-tripped through a double is wrong in exactly the digits a trader
is reading it for. Nice-number ladder (1 / 2 / 2.5 / 5 × 10^k) chosen so labels sit at least
2.5 line-heights apart, with the step floored at one unit of the venue's precision for the
asset so no gridline can quote a price the exchange would reject. Log axes spanning a decade or
more step by decade instead and thin by measured pixel distance.

**Time** (`time_ticks`). Each bar carries the largest calendar boundary it opens on relative to
the bar before it (year > month > week > day > the minor ladder). Ticks are placed
coarsest-tier first, so a month boundary never loses its slot to a day two bars away, and
whatever room is left is filled from a time ladder (1 s … 12 h) picked to fit the current bar
spacing. Labels at the heaviest weight actually on screen are drawn brighter — on a 5-minute
chart that is the day boundaries, with the hours between them quiet. Calendar fields come from
a `civil_from_days` conversion rather than `gmtime_r`: the axis re-derives dates for every
visible bar every frame, and this is branch-free integer work with no libc lock.

### 2.6 Overlays and the price gutter

Position entry, liquidation and every resting order share one `ChartLevel` shape: a dashed rule,
a name chip at the rule's right-hand end, and a price tag in the axis gutter. Order lines cover
only the right 30 % of the pane (TradingView's `setLineLength`) so a book full of resting limits
does not draw a grid over the candles; account-wide levels run the full width.

The gutter is one narrow strip that the crosshair, the last price, the bar countdown, every
level and every gridline label all want. They are placed by rank — crosshair, then orders, then
liquidation, then entry, then the last price — and a tag that would overlap one already placed
simply does not draw. Nudging it would put a price label at a price it is not at. Gridline
labels are drawn last and skip any strip a tag has claimed. Tag text is black or white by
TradingView's luma rule (`0.199R + 0.687G + 0.114B > 160/255`), so a level given an amber or a
teal colour stays readable either way.

A level scrolled off the pane keeps its tag, pinned to the edge with an arrow: a liquidation
price you cannot see is the one you most need told about.

### 2.7 The ruler

Shift+drag (or arm the toolbar's `measure` button for one drag) boxes a region and reads out
what the move was worth: price delta, percent, and the same delta counted in the instrument's
own ticks; the span in bars and in wall-clock time; and the volume traded across those bars. An
arrow per axis runs from the anchor to the release point, so the direction is readable without
parsing the signs.

Two details worth keeping. The anchor is resolved against the axis range the frame *started*
with, not the one committed further down — that is the range the user was looking at when they
pressed, and a frame's difference is a visibly wrong anchor on a fast market. And the ends are
bar indices that may fall outside the series, because measuring into the empty pane past the
last bar ("how long until this reaches that level") is a normal thing to want.

The ruler is `#2962FF`, a colour nothing else on this chart uses. It is scaffolding, not market
data, and must never be mistaken for a level someone put there on purpose. It survives the drag
that made it — the point is to read it afterwards — and is cleared by `Esc` or by a plain click
in the pane.

### 2.8 Cost

At 8 px per bar on a 1600 px pane that is 200 candles × 2 rects per frame. The vertex ceiling
is not a concern either: `ImDrawIdx` is `unsigned short`, but the OpenGL3 backend sets
`ImGuiBackendFlags_RendererHasVtxOffset` and honours `ImDrawCmd::VtxOffset`, so ImGui emits
unlimited-size meshes with 16-bit indices.

**Interaction rules that matter more than they look:**
- Click a book level → limit price into the ticket. The single most-used interaction in any
  trading UI.
- Drag a resting-order line on the chart → modify, behind a confirm threshold.
- Depth bars normalize to the *visible window*, not the whole book, so they stay legible when
  one side is thin.
- The ticket previews the **rounded** price and size — what you see is what gets signed.
- The aggregation dropdown feeds display only. It must not be reachable from execution code
  (03 §W3: aggregation destroys the true touch price).

## 4. Idle cost

A naive ImGui loop calls `glfwPollEvents()` and spins at vsync forever, burning a core. A
trading terminal wants the opposite default: **idle at ~10 fps, jump to 60 fps when something
changes.**

```cpp
constexpr double kIdleFps = 10.0, kActiveFps = 60.0;
std::atomic<bool> g_dirty{false};                 // set by the engine thread

while (!glfwWindowShouldClose(win)) {
    bool active = g_dirty.exchange(false) || ImGui::GetIO().WantTextInput;
    glfwWaitEventsTimeout(1.0 / (active ? kActiveFps : kIdleFps));
    /* NewFrame -> DrawTerminal() -> Render -> SwapBuffers */
}
```

✅ Verified in the local GLFW 3.5.1 header: `glfwWaitEventsTimeout(double)` (glfw3.h:4641)
blocks until an event or timeout; **`glfwPostEmptyEvent(void)`** (glfw3.h:4661, since 3.1) is
the key primitive — the documented way to wake `glfwWaitEventsTimeout` from another thread.

The engine thread writes its snapshot, sets `g_dirty`, then calls `glfwPostEmptyEvent()`. That
gives sub-frame latency on a fill while still idling at 10 fps when the book is quiet.

Two refinements:
- **Do not wake the renderer on every book delta.** At 100+ updates/s you would render above
  60 fps and waste the whole optimization. Rate-limit `glfwPostEmptyEvent` to ~60 Hz, or let
  the timeout coalesce bursts naturally.
- `glfwWaitEventsTimeout` must run on the main thread, and on macOS specifically the thread
  that created the window. This forces "render on main, everything else on workers" — which is
  the right architecture anyway (02 §4).

Upstream: ImGui's position is that idling is deliberately the application's job, so there is no
built-in flag — see the "Implementing Power Save" wiki page.

## 5. Cross-thread structures

### 5.1 Seqlock — "latest order-book snapshot"

The renderer only ever wants the *newest* book, never a history, so a queue is the wrong shape.
A seqlock never blocks the writer and uses no bus-locked instructions.
Reference implementation: `rigtorp/Seqlock` (header-only, MIT).

```cpp
template <typename T> class Seqlock {
  static_assert(std::is_nothrow_copy_assignable<T>::value);
  static_assert(std::is_trivially_copy_assignable<T>::value);
public:
  T load() const noexcept {
    T copy; std::size_t seq0, seq1;
    do {
      seq0 = seq_.load(std::memory_order_acquire);
      std::atomic_signal_fence(std::memory_order_acq_rel);
      copy = value_;
      std::atomic_signal_fence(std::memory_order_acq_rel);
      seq1 = seq_.load(std::memory_order_acquire);
    } while (seq0 != seq1 || seq0 & 1);          // odd == write in progress
    return copy;
  }
  void store(const T& desired) noexcept {
    std::size_t seq0 = seq_.load(std::memory_order_relaxed);
    seq_.store(seq0 + 1, std::memory_order_release);      // -> odd
    std::atomic_signal_fence(std::memory_order_acq_rel);
    value_ = desired;
    std::atomic_signal_fence(std::memory_order_acq_rel);
    seq_.store(seq0 + 2, std::memory_order_release);      // -> even
  }
private:
  static const std::size_t kFalseSharingRange = 128;      // Apple Silicon cache line
  alignas(kFalseSharingRange) T value_;
  std::atomic<std::size_t> seq_;
  char padding_[/* pad to a multiple of 128 */];
};
```

The `static_assert`s enforce trivially-copyable, which conveniently forces `L2Book` off
`std::vector` and onto the fixed-size layout we wanted anyway (02 §6.1).

> ⚠️ **Pedantic but real:** `value_ = desired` is a non-atomic write racing a non-atomic read,
> which is formally UB under the C++ memory model even though it is correct on every real
> architecture. Rigtorp documents this. If it bothers you, the alternative is a triple buffer
> with an atomic index swap — no torn reads, no UB, one extra buffer of memory. Either is
> defensible; pick one deliberately rather than by accident.

### 5.2 SPSC ring — fills, acks, toasts

For streams where *every* item matters, use a bounded SPSC queue. `rigtorp/SPSCQueue`
(header-only, C++11, MIT) caches head/tail locally to cut coherency traffic and pads both
indices and the slot buffer against false sharing.

```cpp
rigtorp::SPSCQueue<Fill> fills{4096};
// engine: if (!fills.try_emplace(f)) ++dropped;  then rate-limited glfwPostEmptyEvent()
// render: while (Fill* f = fills.front()) { apply(*f); fills.pop(); }
```

`moodycamel::ReaderWriterQueue` is a fine alternative; `ConcurrentQueue` is MPMC and more
machinery than needed. Prefer rigtorp's here — smaller, and the cache-line discipline is
explicit and auditable.

### 5.3 No allocation on the hot path

- Preallocate every ring and snapshot at startup. `try_push` returning false is backpressure,
  not a resize signal.
- **The C++ side never parses market-data JSON at all** — Rust does it at the edge and hands
  over POD structs (04 §5). So `nlohmann::json` is confined to config and CLI, where its
  per-node allocation is irrelevant. This is a real benefit of the language split that is easy
  to forget: no `simdjson`, no SAX handler, no DOM on the hot path, because there is no JSON on
  the hot path.
- ImGui reuses its draw buffers across frames, so steady-state frames do zero `malloc` as long
  as panel code doesn't allocate.

## 6. Build

✅ This configures and builds end-to-end (0 errors; the binary printed
`imgui 1.93.0 WIP docking=128`):

```cmake
cmake_minimum_required(VERSION 3.24)
project(parsec LANGUAGES C CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

include(FetchContent)
set(GLFW_BUILD_DOCS OFF CACHE BOOL "" FORCE)
set(GLFW_BUILD_TESTS OFF CACHE BOOL "" FORCE)
set(GLFW_BUILD_EXAMPLES OFF CACHE BOOL "" FORCE)

FetchContent_Declare(glfw   GIT_REPOSITORY https://github.com/glfw/glfw.git
                            GIT_TAG 3.5.1 GIT_SHALLOW TRUE)
FetchContent_Declare(imgui  GIT_REPOSITORY https://github.com/ocornut/imgui.git
                            GIT_TAG v1.92.9b-docking GIT_SHALLOW TRUE)
FetchContent_Declare(json   GIT_REPOSITORY https://github.com/nlohmann/json.git
                            GIT_TAG v3.12.0 GIT_SHALLOW TRUE)
FetchContent_MakeAvailable(glfw imgui json)
find_package(OpenGL REQUIRED)

# imgui ships no CMakeLists — you always build it yourself.
add_library(imgui STATIC
  ${imgui_SOURCE_DIR}/imgui.cpp        ${imgui_SOURCE_DIR}/imgui_draw.cpp
  ${imgui_SOURCE_DIR}/imgui_tables.cpp ${imgui_SOURCE_DIR}/imgui_widgets.cpp
  ${imgui_SOURCE_DIR}/backends/imgui_impl_glfw.cpp
  ${imgui_SOURCE_DIR}/backends/imgui_impl_opengl3.cpp)
target_include_directories(imgui PUBLIC ${imgui_SOURCE_DIR} ${imgui_SOURCE_DIR}/backends)
target_link_libraries(imgui PUBLIC glfw OpenGL::GL)

# Rust staticlib (04 §5.4)
FetchContent_Declare(Corrosion GIT_REPOSITORY https://github.com/corrosion-rs/corrosion.git
                               GIT_TAG v0.5.2 GIT_SHALLOW TRUE)
FetchContent_MakeAvailable(Corrosion)
corrosion_import_crate(MANIFEST_PATH rust/Cargo.toml CRATE_TYPES staticlib LOCKED)

add_executable(parsec src/main.cpp)
target_link_libraries(parsec PRIVATE imgui nlohmann_json::nlohmann_json parsec_rs)
```

**FetchContent over vcpkg or Conan.** For a solo project with a handful of dependencies, FetchContent
is the only option with zero out-of-band state: `git clone && cmake -B build` works on a fresh
machine and in CI with no manifest tool, toolchain file, or lockfile daemon. vcpkg earns its
keep with many heavy binary deps and a binary cache; Conan with multi-package versioning across
teams. Neither pays for itself here. `GIT_SHALLOW TRUE` roughly halves clone time (~33 s cold,
near-zero warm).

## 7. Build gotchas, all hit and verified

**1. The Objective-C++ trap — and why GLFW+OpenGL3 avoids it.** ✅ If you add
`imgui_impl_metal.mm`, `-fobjc-arc` guarded by `$<COMPILE_LANGUAGE:OBJCXX>` **silently does
nothing** unless `OBJCXX` is an enabled language — CMake compiles the `.mm` as plain C++ and
you get `'__bridge_retained' casts have no effect when not using ARC`. Adding
`LANGUAGES C CXX OBJCXX` then **breaks GLFW**, because CMake starts compiling GLFW's `.m` files
as Objective-C++ (errors like `cannot initialize 'CFStringRef *' with an rvalue of type
'void *'`). The only correct incantation is `LANGUAGES C CXX OBJC OBJCXX`. This is a concrete
argument for decision D3 beyond portability.

**2. CMake 4.x and `cmake_minimum_required`.** CMake 4 removed compatibility with
`cmake_minimum_required(VERSION <3.5)`. ✅ The pinned deps here are fine — GLFW 3.5.1 declares
`3.16...3.28`, and even GLFW 3.3.10 configures cleanly because the *range* form is tolerated.
The failure mode is a dep declaring a bare `VERSION 3.0` with no upper range. Escape hatch,
✅ confirmed accepted: `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`, or scope it to the offending dep
with `set(...)` / `unset(...)` around its `FetchContent_MakeAvailable`. Treat it as a temporary
unblock, never a permanent setting.

**3. Pin every `GIT_TAG` to a tag or SHA, never a branch** — with the sole exception of imgui,
where `docking` *is* the release channel. Pin `v1.92.9b-docking` for reproducibility.

**4. Corrosion `v0.5.2`** — the tag was not verified to exist; check before pinning
(`v0.6.1` is current). The `corrosion_import_crate` API and the
`crate-type = ["staticlib"]` requirement come from the docs, and a working
CMake+Corrosion+tokio build is preserved at `prototypes/ffi-demo/`.

**5. Linux is unbuilt.** Everything above was compiled on macOS only. GLFW+OpenGL3 is the
well-trodden path and should port cleanly, but **no Linux build has been run** — do it in
Phase 0 rather than discovering it in Phase 5.

**6. No C++ WebSocket library is needed.** IXWebSocket and Boost.Beast were surveyed, but all
socket work lives in Rust (04). Adding either would duplicate the transport layer.
